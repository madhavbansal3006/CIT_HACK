> **Hackathon Track:** Category C1 — Smarter Water Conservation  
> **Team:** IVISION  
> **Mode:** SOFTWARE SIMULATION MODE (Virtual IoT Twin)

---

## 🌊 Overview

**AquaGuard AI** is an intelligent differential flow monitoring and automatic pipeline isolation system engineered to eliminate municipal and residential clean water loss. 

Because physical water leakage hardware is still in active benchtop development, this project provides a **complete, high-fidelity, interactive Web Simulation Dashboard** accompanied by an **ESP32 microcontroller firmware starter (Wokwi-ready)**.

> ⚠️ **Important Boundary Notice:**  
> - This dashboard operates strictly in **SIMULATION MODE**. Telemetry readings, flow noise, and shutoff responses are generated by software physics models.
> - This system is **completely separate** from the working physical *JalDrishti* rainfall and water-quality hardware setup. No hardware configurations or physical sensors from JalDrishti have been altered or combined.
> - A differential flow rate is an indicator of a **possible leak**, not definitive proof. Production deployments require K-factor calibration, branch consumption heuristics, and acoustic verification.

## 🚀 Key Features

1. **Live Dual Flow Sensor Telemetry:**
   - Simulated Flow Sensor 1 (Inlet / Upstream, modeled after Hall-effect YF-S201 on GPIO 18).
   - Simulated Flow Sensor 2 (Outlet / Downstream, modeled after Hall-effect YF-S201 on GPIO 19).
   - Real-time Differential Flow calculation: $\Delta Q = Q_{inlet} - Q_{outlet}$.

2. **Animated Pipeline Visualization:**
   - Conceptual topology: **Source Tank → Centrifugal Pump → Inlet Sensor → Pipe Fracture Point → Outlet Sensor → Motorized Isolation Valve → Destination Tank**.
   - Dynamic fluid motion, rotating pump impellers, turbine pulse badges, and animated pipe fracture with escaping water droplets during leak injection.

3. **Intelligent Leak Detection & Auto-Shutoff Heuristic:**
   - Configurable trip threshold (default `2.0 L/min`).
   - Anti-jitter persistence filter (default `3 seconds` of sustained violation) to prevent false trips caused by water hammer, air pockets, or sensor noise.
   - Automatic execution: Pump shut down (GPIO 26 Relay 1), valve closed (GPIO 27 Relay 2), flow ceased, audit trail event logged.

4. **Category C1 Smarter Water Conservation Analytics:**
   - Real-time accounting of Total Water Pumped, Delivered Downstream, Lost in Leak, and **Water Conserved by Auto-Shutoff**.
   - Delivery efficiency index (%).

5. **Live Time-Series Charting:**
   - Dual-area chart (Recharts) plotting Inlet (Blue) vs. Outlet (Teal).
   - Dynamic reference threshold line with breach zone indicator.

6. **Judge Demonstration Presets (1-Click Demo Scenarios):**
   - **Demo A:** Normal Flow ($\Delta Q < 0.3$ L/min, safe baseline).
   - **Demo B:** Discrepancy Below Threshold ($1.1$ L/min difference, demonstrates false-positive rejection).
   - **Demo C:** Persistent Possible Leak ($3.2$ L/min loss, trips auto-shutoff after 3s).
   - **Demo D:** Major Simulated Pipe Fracture ($5.8$ L/min burst, rapid trip).
   - **Demo E:** Manual Operator Pump Stop.
   - **Demo F:** Auto-Shutoff Disabled (demonstrates unmitigated water loss baseline).

7. **Audit Trail & Event Log:**
   - Timestamped event entries with severity filters (All, Alerts, Actions) and clear log capabilities.

8. **Presentation Aids:**
   - **Projector Mode Toggle:** Boosts contrast, font weight, and element padding for classroom/auditorium projectors.
   - **IoT Engineering & Physics Modal:** Deep dive on Hall-effect K-factors ($F = 7.5 \times Q$), transient water hammer mitigation, and hardware isolation.

## 🛠️ How to Run the Web Simulation

### Prerequisites
- Node.js (v18+ or LTS, tested on v22.x)
- npm (v9+)

### Installation & Launch

```bash
# Navigate to the web-simulation directory
cd web-simulation

# Install dependencies (already installed)
npm install

# Start local development server with Hot Module Replacement
npm run dev
```

Open the local URL displayed in your terminal (typically `http://localhost:5173`).

### Production Build & Preview
To verify the production build:
```bash
npm run build
npm run preview
```

## 🎯 Hackathon Judge Demo Sequence (3-Minute Presentation)

1. **Step 1: Baseline Normal Flow (30 seconds)**
   - Click **Demo A (Normal Flow)** or observe the default state.
   - Point out the twin flow sensors ($Q_{in} \approx 12.3$ L/min, $Q_{out} \approx 12.1$ L/min).
   - Highlight that the flow difference ($\approx 0.2$ L/min) is well within the $2.0$ L/min threshold line on the Recharts graph.

2. **Step 2: Proving False-Positive Rejection (45 seconds)**
   - Click **Demo B (Discrepancy Below Threshold)**.
   - Notice that a $1.1$ L/min discrepancy is introduced, but AquaGuard AI **does NOT** trip an alarm or shut down.
   - *Judge explanation:* Explain that real IoT sensors (like the YF-S201) have a $\pm3\%\text{--}5\%$ error margin, and plumbing systems have natural turbulence. The system is designed to reject noise without unnecessary water cutoffs.

3. **Step 3: Injecting a Sustained Leak & Auto-Shutoff (60 seconds)**
   - Click **Demo C (Persistent Leak)** or press **Inject Leak** at $3.2$ L/min.
   - Watch the pipeline visualization: the leak point highlights with spraying water particles and an alert badge.
   - Watch the persistence counter in the Telemetry card: `Sustained: 1s... 2s... 3s / 3s`.
   - At 3 seconds, witness the automatic emergency reaction:
     - Pump turns **OFF** (GPIO 26 signal LOW).
     - Valve turns **CLOSED** (GPIO 27 signal LOW).
     - Status updates to **AUTO SHUTOFF**.
     - Water flow ceases, and an audit trail entry is logged.
   - Point to the **Water Conservation Analytics card**: show how the system quantifies water conserved by stopping the leak immediately.

4. **Step 4: Baseline Risk Comparison (30 seconds)**
   - Toggle **Automatic Shutoff to OFF** (or click **Demo F**).
   - Start flow and inject a leak. Show that water continues escaping indefinitely without automation, underscoring the necessity of AquaGuard AI for Smarter Water Conservation.

5. **Step 5: Physical Hardware Architecture (15 seconds)**
   - Click **IoT Engineering** in the top bar.
   - Briefly walk through the ESP32 pin table, the continuity equation $\Delta Q = Q_{in} - Q_{out}$, and explain how this software simulation translates directly to the ESP32 Wokwi controller circuit.

## 🔌 ESP32 Microcontroller Controller Map (Hardware Target)

| Function | ESP32 GPIO | Electrical Interface | Role |
|:---|:---:|:---|:---|
| Inlet Flow Sensor (YF-S201) | GPIO 18 | External Interrupt (FALLING) | Pulse frequency monitoring ($F = 7.5 \times Q$) |
| Outlet Flow Sensor (YF-S201)| GPIO 19 | External Interrupt (FALLING) | Downstream consumption monitoring |
| Test Leak Injection Button | GPIO 25 | Active-LOW Input (`INPUT_PULLUP`) | Hardware benchtop test button |
| Centrifugal Pump Driver | GPIO 26 | Optocoupled Relay / MOSFET | Pump power isolation (flyback diode protected) |
| Motorized Isolation Valve | GPIO 27 | Optocoupled Relay | Emergency pipe isolation (Normally Closed) |
| System Status LED | GPIO 2 | Digital Output | Heartbeat & alarm indicator |
